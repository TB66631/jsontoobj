## 自动资源引用可以越出包目录：待修复

`resolveResource()`（`nmtm.js:63`）会规范化 JSON 中的相对引用，并尝试源文件目录、模型和贴图目录，但没有检查最终候选是否留在资源根内。函数用于自动查找贴图、变体 mesh、skeleton 和 animation。纯内存探针对当前函数确认，`../../outside.json`、反斜杠变体和相似前缀的同级目录都可以返回包外目标；找不到包根时仍然有该行为。没有读取真实包外文件。

`importLegacy()`（`nmtm.js:534`）还将 JSON 的 `geometry.*` 后缀直接拼成 PNG 路径，绕过上述 resolver。只修一个函数不足以收口所有自动读取路径。现有 `statSync` 会跟随链接，路径流程没有 `realpath` 校验；链接逃逸属于源码与 API 语义推导，本次未制作真实链接利用。

后续修复需要：

- 在一次导入中保持稳定的资源根上下文；自动引用不能通过换一个源文件位置扩大授权范围。
- 对每个候选做规范化路径包含检查，并对实际存在文件再做 canonical 路径包含检查；覆盖 sibling、自动动画发现及 legacy 自动贴图入口。
- 明确定义没有资源包根时的 standalone 配对范围，保留正常的模型、骨骼、动画伴随文件。
- 保留合法包内 `../textures/...`。不能简单禁止所有 `..`，也不能用裸字符串前缀判断目录包含。
- 明确处理 Windows 盘符、UNC、设备路径、ADS 和大小写；当前 `path.join()` 没有把后续盘符自动当作新根，不能把它误报为已证实的任意盘跳转。
- 区分用户主动选择的外部文件和 JSON 自动引用。正常包内读取不增加确认弹窗；用户明确选中的文件不因该边界检查被无故拒绝。

修复后的回归应包括包内合法引用、越界与相似前缀、Windows 路径、缺失根、词法包内但 canonical 包外、legacy 名称和正常伴随文件；不依赖 GUI 或私有素材。

## PNG 解码缺少前置上限：待修复

`textureBuffer()`（`nmtm.js:764`）会先完整读取文件或解码 base64。`decodePngRgba()`（`nmtm.js:779`）在校验部分 PNG 格式字段后，于第 812 行调用未设置 `maxOutputLength` 的 `inflateSync`，并根据未受统一上限约束的宽高分配 raw、scanline 和 RGBA 缓冲。

`buildEmfTextureAtlas()` 的 8192×8192 图集限制在所有源图解码之后；单贴图分支还会提前返回。该检查不能限制之前的文件读取、解压或像素内存分配。影响主要是需要此解码器的 EMF atlas 导出路径，不代表普通贴图预览都会经过它。

安全小探针确认：1×1 正常像素可解码，但其扫描线后多出 32 bytes 仍被接受；通过 stub 解压和受控分配器，8193×8193 的声明会申请 268,500,996 bytes，极端宽高会产生非安全整数字节数。探针在超过 4096 bytes 的分配前阻止操作，真实展开数据最多 64 bytes，没有实际制造大额分配或复现崩溃。测试 Node 支持 `maxOutputLength`，Blockbench Electron 的实际能力仍需后续单独核对。

后续修复需要在读取、分配和解压前分别限制输入文件/数据大小、宽高、总像素、乘法安全性和预期 scanline 输出量，并将解压输出上限传给 zlib。Adam7 各 pass 也应计算准确预算。超限与格式异常应给出明确报错，保留当前支持的正常 PNG 类型、透明度及标准/Adam7 扫描线。

测试使用小型合法图片和极小合成头部，验证超限输入在解压、分配前被拒绝；不得以实际耗尽内存或大规模压缩炸弹作为验收方式。内存预算的具体数值需要结合正常贴图、atlas 总量和峰值缓冲确定，本页没有将建议上限当作已实现配置。
